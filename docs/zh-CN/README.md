## 记录状态

- **草稿：** 正在评审，尚不能作为决策事实源。
- **已验证：** 已在标明日期对照当前代码和测试。
- **历史：** 为保留决策理由而存在，不代表当前行为。
- **生成：** 由机械流程产生；应重新生成而不是手工编辑。

若文档与实现不一致，按根目录 `AGENTS.md` 的优先级判断，并在同一变更中修复文档。

## 如何修改文档

1. 更新最小的英文权威记录。
2. 更新 `docs/zh-CN/` 中对应文件。
3. 范围或权威性变化时更新目录、状态、负责人和验证日期。
4. 通过链接引用详情，不要复制到 `AGENTS.md` 或另一个概览中。
5. 运行 `python scripts/check_docs.py` 和 `python -m pytest tests/test_docs.py`。

新的设计决策放入 `design-docs/`；跨模块实施工作放入 `exec-plans/`。完成的计划应移动并
保留理由。用户可见行为属于 README/产品契约，运行细节属于 `references/`。

维护中的 Python 函数和类使用精简、语义化的中文说明处理逻辑、输入和输出。输入要指出
上游来源及实际消费的信息，输出要说明结果对下一阶段的意义；只复述类型或函数名会被
`python scripts/check_code_comments.py` 拒绝。行内注释聚焦不直观的决策。

## 语言策略

英文是共享的智能体和贡献者接口，因此是权威工程记录。中文译文是面向维护者的可审阅
镜像，必须在同一次变更中更新。译文不能静默增加英文原文中不存在的规则。
