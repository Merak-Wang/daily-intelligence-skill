# 核心理念

**状态：** 已验证
**负责人：** 仓库维护者
**最后验证：** 2026-08-02

1. **仓库就是记录。** 本地代码、版本化 artifact、测试和相互链接的文档，必须足以
   重建系统为何如此运行。
2. **给智能体一张地图，而不是一本手册。** 小型入口文档把情境留给真正相关的任务、
   代码和证据。
3. **用确定性系统包围模型判断。** 模型可以选择和写作；Python 必须拥有身份、状态、
   校验、限额和持久化。
4. **失败也是数据。** 访问拒绝、限流和部分采集必须显式保留；伪装成空成功会污染决策。
5. **本地事实优先于远程便利。** JSON/Markdown 是事实源；HTML、PDF、桌面副本和
   Notion 是可重试投影。
6. **情境和成本都是预算。** 采集可以广，但证据 Packet、写作批次和分析 Dossier 必须有界。
7. **兼容是明确边界。** 旧版来源索引结构继续可读，直到一次有测试和发布说明的主动迁移。
8. **文档必须可测试。** 目录覆盖、翻译配对、链接完整性和入口文件大小都应机械检查。
9. **生成副本位于下游。** 只在规范事实源实现一次，再重建发布 artifact；不要手工维护多份
   漂移实现。
10. **已知债务保持可见。** 记录范围明确的后续动作和证据，不要把差距埋进宽泛指令文件。
11. **注释解释契约和选择。** 维护中的定义用精简中文说明处理逻辑、输入来源和消费字段，以及
    输出对下游的意义；类型和标识符改写不构成说明。行内注释只用于不直观的安全、状态、兼容、
    并发和恢复决策。

英文权威版本见 [`core-beliefs.md`](../../design-docs/core-beliefs.md)。
