# 端到端流程

## CLI 初始化

`daily_intelligence.cli.main()`：

1. 解析全局参数和子命令；
2. 从 Hermes Home 加载 `.env`，`override=False`；
3. 加载 YAML，构建类型化 `AppConfig`；
4. 解析数据根并确认与 Hermes 绑定一致；
5. 将配置、路径和显式选项传入业务函数。

全局参数放在子命令前：

```powershell
daily-intel --config CONFIG --data-dir DATA_DIR --timezone Asia/Shanghai COMMAND
```

## 0. 零 Token 监控

```powershell
daily-intel refresh-monitor
daily-intel monitor-status
daily-intel serve --open --refresh-minutes 30
```

`refresh_monitor()`：

1. 选择核心与发现来源，可按 source、bundle 或 `--core-only` 过滤；
2. 读取 Feed Registry 和缓存；
3. 按刷新间隔执行条件请求；
4. 发现并解析 RSS/Atom；
5. 无 Feed 条目时对通用来源执行静态 HTML 回退；
6. 合并当前结果与保留期内历史条目；
7. 更新来源健康；
8. 运行确定性跨来源聚类；
9. 原子写入 `monitor/snapshot.json`。

这一层不启动 Hermes 写作，也不调用模型。情报台只读 Snapshot 和静态资源，默认监听 `127.0.0.1`；绑定远程地址必须显式传 `--allow-remote`。

## 1. Prepare Edition

```powershell
daily-intel run-edition --edition morning --profile-dir PROFILE_DIR
daily-intel run-edition --edition evening --profile-dir PROFILE_DIR
```

`prepare_edition()`：

1. 获取 `{date}-{edition}` 排他锁；
2. 创建或恢复 Run manifest；
3. 同步已有用户反馈，失败只记录 warning；
4. 复用 90 分钟内的有效 Monitor Snapshot，缺失或过期时尝试刷新；
5. 正式采集 32 个核心来源；
6. 保存不可变 Index；
7. 汇总来源状态和待验证来源；
8. 读取历史 Report、Evaluation、语义缓存和连续状态；
9. 构建 Context、Brief Plan 与最多三个批次 Packet；
10. 将 Run 置为 `awaiting_selection`。

监控失败不会阻断正式采集。默认不打开浏览器验证窗口；`--open-verification` 是显式交互入口，计划任务不应使用。

## 2. 正文选择与富化

模型或主 Agent 先从 Context 选择需要完整证据的条目，再一次性调用：

```powershell
daily-intel enrich-edition `
  --run RUN.json `
  --item-id ID1 `
  --item-id ID2 `
  --profile-dir PROFILE_DIR
```

`enrich_edition()`：

1. 校验 Run、Index 和数据根；
2. 合并本次与此前已接受 ID；
3. 按调用顺序应用每版 12 条硬上限；
4. 到达总时限后停止新正文读取；
5. HTTP 并发提取正文，复用已有内容；
6. 仅对网络失败或 JavaScript 空壳等可受益页面回退浏览器；
7. 保存正文 Markdown 并生成新 Index Revision；
8. 重建 Context 与写作 Packet；
9. 记录请求、接受、访问结果和并发指标；
10. 将 Run 置为 `awaiting_authoring`。

正文失败保留 `metadata_only`、`verification_required` 或 `failed`，不伪造正文。

## 3. 分批 Brief 写作

开始限时写作 Session：

```powershell
daily-intel begin-authoring --run RUN.json
```

Session 将每个 `brief_authoring_batch.packet_path` 分配给一个模型子任务。子任务的边界是：

- 只读自己的 Packet 和 Packet 列出的 `content_path`；
- 不浏览、不搜索、不读取其他批次；
- 只写分配的 `draft_result_path`；
- 返回所有 `author_item_ids` 的中文标题、TL;DR、重要性和状态；
- 执行一次指定的提交命令。

提交命令：

```powershell
daily-intel submit-authoring-batch `
  --run RUN.json `
  --batch-id brief-batch-1 `
  --result ASSIGNED-DRAFT.json
```

Python 校验：

- 条目 ID 完整、唯一且属于该 Packet；
- 非中文原题具有自然中文翻译；
- TL;DR 有实质中文内容；
- 重要性为 0—100 整数；
- 状态属于 `NEW/UPD/CONF/REV/WATCH/CLOSED`。

通过后写入不可变 Receipt。

## 4. 图片预取与写作指标

Brief 子任务运行期间可以并行：

```powershell
daily-intel prefetch-media --run RUN.json
```

该命令只使用 Index 中的公开图片候选，复用图片缓存并遵守大小、像素、DNS、全局和同域并发边界。

Hermes 批次完成后，可提交有界指标：

```powershell
daily-intel record-authoring-metrics `
  --run RUN.json `
  --metrics delegation-metrics.draft.json

daily-intel authoring-status --run RUN.json
```

允许保存耗时、API 调用、输入/输出 Token、模型、退出原因和可选队列/首 Token/缓存指标；不得保存摘要正文或隐藏推理。

## 5. 准备紧凑分析包

所有批次完成后：

```powershell
daily-intel prepare-analysis --run RUN.json
```

Python：

1. 合并可复用 Brief 与批次 Receipt；
2. 按 Brief Plan 构建七个栏目；
3. 写入 `brief-skeleton.json`；
4. 选择最多 18 个分析候选；
5. 加入最近连续报告、活跃研判、观察项、预测和用户反馈；
6. 写入 `analysis-packet.json`；
7. 将 Session 置为 `analysis_pending`。

只有超过 `analysis_deadline_at` 且仍有缺失批次时，才可执行：

```powershell
daily-intel prepare-analysis --run RUN.json --allow-degraded
```

降级结果会缩小 Run 自有覆盖目标，并明确记录缺失批次；不能冒充完整日报。

## 6. 研判与确定性装配

主模型只读取 Analysis Packet，输出：

- 标题与摘要；
- 6—10 个 Featured Event；
- 三个固定分析域；
- `cross_perspective_synthesis`。

写入 Packet 指定的 `analysis_result_path` 后执行：

```powershell
daily-intel assemble-authoring `
  --run RUN.json `
  --analysis ANALYSIS.json
```

`assemble_report_draft()` 把模型分析合并进 Python 构建的 Brief Skeleton，写入 schema 2.0 `report-draft.json`，并将 Session 置为 `ready`。

## 7. 验证

```powershell
daily-intel validate-report REPORT-DRAFT.json --run RUN.json
```

验证层次：

1. JSON Schema；
2. 报告内部跨字段关系；
3. 报告与当前 Index 的标题、URL、来源、时间和访问身份；
4. Run 自有覆盖目标与 Enrichment lineage。

当前 Context 是 2.0 时，1.5 草稿会被拒绝，不能绕过跨视角综合。只有输出 `errors: 0` 才进入 Finalize。

## 8. HTML 前台交付

```powershell
daily-intel finalize-edition `
  --run RUN.json `
  --report REPORT-DRAFT.json `
  --defer-tail
```

`finalize_edition()`：

1. 再次检查 Context schema、lineage 和覆盖目标；
2. 编译并校验报告；
3. 下载和绑定公开图片；
4. 分配 Report Revision；
5. 保存不可变 JSON/Markdown；
6. 生成本地 HTML 和日报索引；
7. 生成桌面 HTML；
8. 写入语义缓存待评状态；
9. 将 Run 标为本地完成；
10. 写入 `tail.status: pending` 与 `tail.command`。

命令返回后即可交付 `artifacts.html_path` 和 `artifacts.desktop_html_path`。桌面失败只记录 `desktop_html_error`。

## 9. 后台 Tail

```powershell
daily-intel complete-edition-tail --run RUN.json
```

若前台请求了 Notion：

```powershell
daily-intel complete-edition-tail --run RUN.json --publish
```

Tail：

1. 重建带 PDF 链接的 HTML 与桌面投影；
2. 使用 Edge 生成 PDF，失败时降级 ReportLab；
3. 显式请求时发布或续传 Notion；
4. 调度最多三次、间隔约两分钟的独立 Evaluation；
5. 写入里程碑、耗时、错误和下一动作。

重复调用是幂等的。若已有 `tail.status: completed`，直接返回。

## 10. Independent Evaluation

评估 Agent 完成后调用：

```powershell
daily-intel finalize-evaluation `
  --report REPORT.json `
  --evaluation EVALUATION.json
```

原 Report 已发布到 Notion 时才附加 `--publish`。

该阶段：

- 验证被评 Report ID 与内容 Hash；
- 保存不可变 Evaluation；
- 更新语义缓存和连续状态；
- 重建 HTML、桌面 HTML 和 PDF 评估区域；
- 可选追加同一 Notion 页面。

评估失败或分数低不会撤回报告，只影响后续语义复用和改进。

## 人工验证

```powershell
daily-intel verify-pending `
  --index INDEX.json `
  --profile-dir PROFILE_DIR `
  --browser-channel msedge
```

队列只处理 `failed`、`verification_required` 和 `rate_limited` 链接。用户点击后，页面出现可提取条目才保存结果。限流来源停止本轮重试；未成功链接继续保留。合并后生成新 Index Revision，不覆盖旧报告。

## 恢复表

| 情况 | 恢复方式 |
| --- | --- |
| Monitor 失败 | 正式核心来源采集继续；下轮重刷 Snapshot |
| 单来源失败 | 保留状态并继续 partial 报告 |
| 限流 | 本轮停止浏览器重试，后续再尝试 |
| 正文失败 | 保留元数据与访问状态 |
| 批次缺失 | 截止前等待；截止后显式 `--allow-degraded` |
| 草稿校验失败 | 修复指定字段，不反复试错 Finalize |
| 桌面写入失败 | 修复绝对 `desktop_dir`，重建投影 |
| PDF 失败 | Tail 重试；Edge 失败自动用 ReportLab |
| Notion 失败 | 同一 Tail 或发布命令续传 |
| Evaluation 调度失败 | 保留本地报告，单独重试调度/评估 |
| 锁冲突 | 核对进程、Run 与锁内容，不批量删除 |
