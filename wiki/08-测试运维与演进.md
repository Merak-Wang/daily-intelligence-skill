# 测试、运维与发布

## 本地检查

```powershell
python -m pip install -e ".[dev]"
python -m ruff check .
python -m pytest
python -m compileall -q src tests
daily-intel --help
git diff --check
```

Skill 结构校验：

```powershell
$env:PYTHONUTF8 = "1"
python C:\path\to\skill-creator\scripts\quick_validate.py .
```

CI 在 Windows 和 Ubuntu、Python 3.11/3.12 上执行 Ruff、pytest 和 compileall。

## 测试分层

| 文件 | 覆盖范围 |
| --- | --- |
| `tests/test_config.py` | 配置、资源目录、数据根、来源页 |
| `tests/test_feeds.py` | RSS/Atom、Feed 发现、条件缓存和刷新 |
| `tests/test_monitor.py` | Snapshot、健康、Filter 和 Feed/HTML 回退 |
| `tests/test_clustering.py` | 词法向量、事件簇、阶段和重要性 |
| `tests/test_normalize.py` | URL、标题、日期和来源过滤 |
| `tests/test_prefetch.py` | 静态 HTML 预取、并发和浏览器回退判定 |
| `tests/test_content.py` | 正文 HTTP 优先、缓存、并发和 Edge 回退 |
| `tests/test_media.py` | 图片安全、缓存、下载、投影与 Notion 上传 |
| `tests/test_authoring.py` | Session、批次、指标、分析包和装配 |
| `tests/test_reporting.py` | Schema、编译、证据与语义校验 |
| `tests/test_architecture.py` | Workflow、Artifact、恢复、HTML/PDF/Notion |
| `tests/test_desktop_delivery.py` | 桌面图片内嵌、PDF 图片对象、绝对导航链接、原子交付和失败状态 |
| `tests/test_importer.py` | 旧 source-index 导入与状态修复 |
| `tests/test_semantics.py` | 语义指纹、Evaluation 门槛和复用 |
| `tests/skills/` | Skill 入口和 Notion 断点续传 |

测试不得访问真实 Notion、使用真实 Token、复用用户浏览器 Profile 或读取运行时数据根。外部服务用 Fake Client、Mock Transport 和临时页面替代。

## 变更与最低测试

| 变更 | 最低覆盖 |
| --- | --- |
| Feed 或来源过滤 | 接受、拒绝、日期、图片、缓存 |
| Source/Content 状态 | 成功、空、部分、失败、验证、限流 |
| Monitor | 83 来源选择、Snapshot、健康、零 Token |
| 聚类 | 稳定 ID、阈值、时间窗、阶段、重要性 |
| 并发 | 全局上限、同域上限、异常释放 |
| Authoring | Packet 边界、Receipt、指标、截止与降级 |
| 报告字段 | Schema、编译、跨字段、证据和所有投影 |
| 存储 | 原子写、Revision、锁和跨数据根拒绝 |
| 图片 | DNS、格式、大小、缓存、并发、失败继续 |
| 桌面输出 | 内嵌媒体、绝对索引/PDF 链接、目录失败 |
| Notion | Schema、HTML 附件、幂等、中断续传、重发、旧版图片回填 |
| 兼容逻辑 | 至少一个旧格式 Fixture |

## 快速定位

建议先运行最小测试：

```powershell
python -m pytest tests/test_authoring.py -q
python -m pytest tests/test_desktop_delivery.py -q
python -m pytest tests/test_monitor.py tests/test_feeds.py -q
```

确认局部通过后再运行完整套件。不要用反复执行真实 Finalize 代替纯校验测试。

## 手动冒烟

按变更范围选择：

```powershell
daily-intel refresh-monitor --source SOURCE_ID --force
daily-intel monitor-status
daily-intel collect --edition morning --source SOURCE_ID
daily-intel verify-pending --index INDEX.json
```

本地投影冒烟：

- 用合成 Report 和 Index 生成 HTML/PDF；
- 在窄屏和打印媒体检查目录、图片、分页和搜索；
- 检查 `reports/index.html`；
- 使用临时绝对 `desktop_dir` 验证桌面投影；
- 检查图片已内嵌且所有剩余 `file:///` 导航目标存在；
- 不在生产 Notion 做普通冒烟。

## 运行指标

Run 应提供：

- 采集来源数、候选数、状态分布；
- Monitor 刷新或快照复用；
- 正文请求、接受、成功和并发；
- Brief 批次耗时、API、Token、模型和退出原因；
- Brief 装配、分析和保存阶段耗时；
- HTML、PDF、Notion 里程碑；
- Tail 总时长和 PDF 投影时长；
- deadline 与 budget 是否耗尽。

指标用于找出真实瓶颈，不用于保存新闻正文、提示词或隐藏推理。

## 故障定位

| 现象 | 首先检查 |
| --- | --- |
| Monitor 条目少 | Feed Registry、缓存刷新时间、HTML 回退 |
| 来源误记 `no_items` | HTTP 状态、挑战分类、URL 过滤 |
| 同一新闻重复 | `canonicalize_url()`、来源内去重、聚类阈值 |
| 正文未进入 Context | 选中 ID、硬上限、Index Revision、lineage |
| 批次无法提交 | Packet ID、指定 Draft 路径、目标语言和状态校验 |
| `prepare-analysis` 拒绝 | 缺失 Receipt、`analysis_deadline_at` |
| 报告校验失败 | Schema 2.0、Index 身份、固定域、综合引用 |
| 桌面无图 | 是否由桌面投影生成、图片是否为有效 `data:` URI |
| PDF 缺失或无图 | `tail.status`、Edge 图片加载、ReportLab 图片对象计数 |
| Notion 404 | Connection 权限与 `data_source_id` |
| Evaluation 未应用 | Report ID、Hash、评分门槛和排除范围 |
| Run 无法恢复 | 状态、锁、数据根、Artifact 路径 |

用户侧恢复命令见 `references/runbook.md`。

## 发布检查

1. 工作区只有预期变更；
2. 无 `.env`、运行数据、Profile、Cookie、认证 HTML 或账户截图；
3. 示例 HTML 无本机绝对路径和凭证；
4. 版本号、Changelog 和 Release Notes 一致；
5. README 与 Wiki 相对链接有效；
6. 合成 Fixture 通过当前 Schema；
7. Ruff、pytest、compileall 和 Skill 校验通过；
8. Wheel/Sdist 在干净环境中可定位 Skill 资源；
9. Release 说明列出兼容变化和已知限制。

构建产物放在 `dist/`，临时审计结果不放仓库根目录，也不替代 CI。

## 演进原则

- 真实运行暴露的问题先落到状态、测试和可重试路径，再改提示词。
- 性能优化必须保留证据边界、覆盖和失败可见性。
- 新来源先进入发现层观察健康，再决定是否升级为核心来源。
- 新 schema 先实现兼容读取，再切换新 Context，最后删除旧写入路径。
- 任何远程发布扩展都不能改变本地优先和不可变事实源。
