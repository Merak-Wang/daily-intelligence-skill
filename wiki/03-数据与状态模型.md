# 数据与状态模型

## 采集实体

`models.py` 定义正式采集的基础类型：

| 类型 | 关键字段 |
| --- | --- |
| `ArticleItem` | `item_id`、来源、原题、URL、规范 URL、发现/发布时间、正文状态、公开摘要、图片 |
| `SourceResult` | 来源身份、状态、HTTP 状态、错误、挑战、逐页结果和条目 |

`item_id` 由 `source_id` 与规范 URL 生成。同一来源的同一规范 URL 必须稳定；不同来源转载同一文章可以保留不同 ID。

## 来源状态

`SourceStatus`：

| 状态 | 含义 |
| --- | --- |
| `success` | 访问成功且得到合格候选 |
| `partial` | 部分入口成功，另一些入口失败或受限 |
| `verification_required` | 合法访问仍需人工登录或验证 |
| `rate_limited` | HTTP 429 或明确临时访问限制 |
| `failed` | 网络、服务端、配置或解析失败 |
| `no_items` | 页面成功访问并确认没有合格条目 |

401、403、429、挑战页、临时限制和解析异常都不能记为 `no_items`。监控快照还可能出现 `unsupported`，表示当前监控协议没有可用 Feed/静态回退结果；正式 Index 仍使用 `SourceStatus`。

## 正文状态

`ContentStatus`：

| 状态 | 含义 |
| --- | --- |
| `not_fetched` | 未尝试正文 |
| `full_text` | 保存了可用正文 |
| `partial` | 保存了部分正文 |
| `metadata_only` | 只有标题或公开元数据 |
| `verification_required` | 正文页需要人工验证 |
| `failed` | 正文提取失败 |

报告 `source_ref.access` 从 Index 状态映射，模型无权自行提升访问级别。

## Monitor Snapshot

`monitor/snapshot.json` 使用 schema 2.0：

```text
schema_version, generated_at, timezone
token_usage, collection_mode
summary
sources[]
items[]
clusters[]
pending_verifications[]
health[]
```

`clusters[]` 不是报告 Featured Event。它是确定性新闻流视图，包含稳定 `story_id`、代表条目、来源集合、阶段和重要性。

Cluster phase：

| 阶段 | 条件 |
| --- | --- |
| `new` | 单一来源且没有上一快照成员 |
| `developing` | 至少两个来源 |
| `confirmed` | 至少三个来源 |
| `updated` | 旧事件簇增加了新条目 |

## Run 状态

`workflow.RunStatus`：

```text
created
  → collecting
  → building_context
  → awaiting_selection
  → extracting_content
  → awaiting_authoring
  → finalizing
  → publishing
  → completed | completed_partial

不可恢复异常 → failed
```

Run manifest 记录：

- 日期、edition、时区、数据根和 attempt；
- `stage_timestamps` 与去重后的 `stage_history`；
- 采集窗口、总时限和分析预留；
- Index、Context、Authoring、Report、HTML/PDF/Notion Artifact；
- 待处理来源、错误、下一动作；
- 写作、图片、保存、Tail 和阶段耗时；
- 发布与 Evaluation 调度状态。

`completed` 表示本地事实源已经交付，不代表 Tail 或 Evaluation 已结束。

## Authoring 状态

`AuthoringStatus`：

| 状态 | 含义 |
| --- | --- |
| `dispatched` | 批次路径已分配，等待模型结果 |
| `analysis_pending` | 批次齐全，分析包已生成 |
| `ready` | schema 2.0 草稿已装配 |
| `degraded` | 分析截止后允许缺失批次，以缩小覆盖继续 |

Session 绑定：

- Run attempt；
- Context 路径与 SHA-256；
- 每批 Packet、Draft Result 和不可变 Receipt；
- `analysis_deadline_at`；
- 委派耗时、API、Token、模型和退出原因；
- Skeleton、Analysis Packet 和 Report Draft 路径。

不同 Context 或 attempt 的批次不能混用。

## 报告模型

当前写作协议是 schema 2.0；Schema 文件仍支持读取 1.1—1.5。

| 字段 | 说明 |
| --- | --- |
| `report_id`、`revision` | 报告身份 |
| `date`、`edition`、`generated_at` | 时间身份 |
| `language` | `zh-CN` 或 `en`；由 run 固定并传入 Context、Packet 与 Report |
| `sections[].briefs` | 宽覆盖层 |
| `sections[].items` | 精选事件层 |
| `analyses` | 三个固定分析域 |
| `analysis_protocol_version` | schema 2.0 固定为 `2.0` |
| `cross_perspective_synthesis` | 共识、分歧、传导、观察和修正 |
| `changes` | 相对上一版的新增、确认和修正 |
| `tomorrow_watch_items` | 晚报次日观察 |
| `pending_verifications` | 访问未完成的来源 |
| `source_metrics` | 配置、成功、代表和待处理计数 |

`compile_report_data()` 注入确定性身份、引用、状态、来源排名、计数、时间和对应语言的栏目标签；不会补写标题翻译、TL;DR 或研判。语义缓存条目同时记录语言，旧缓存缺少该字段时按 `zh-CN` 读取，不能跨语言复用。

## Evaluation

Evaluation 单独保存，至少包含：

- `evaluated_report_id` 和 `evaluated_content_hash`；
- 九个固定评分维度与总分；
- 主要缺陷、证据不足和改进项；
- `continuity_decision` 与排除范围。

Evaluation 完成后：

- 更新语义缓存是否可复用；
- 更新连续状态；
- 重建 HTML、桌面 HTML 和 PDF 的评估区域；
- 仅在显式要求时追加到已有 Notion 页面。

原 Report JSON/Markdown 和内容 Hash 不变。

## Tail 状态

Run 的 `tail` 使用独立状态：

| 状态 | 含义 |
| --- | --- |
| `pending` | 前台 HTML 已交付，尾部尚未开始 |
| `running` | 正在生成 PDF、发布 Notion 或调度评估 |
| `completed` | 请求的尾部工作完成 |
| `partial` | 至少一项失败，可用同一命令重试 |

`tail.errors`、`tail.warnings` 和 `next_action` 必须可操作。尾部状态不能把 Run 从本地完成状态改回失败。

## 文件布局

```text
DATA_DIR/
├─ monitor/
│  ├─ snapshot.json
│  ├─ health.json
│  ├─ feed-registry.json
│  └─ feed-cache/
├─ runs/YYYY-MM-DD/{edition}.json
├─ indexes/YYYY-MM-DD/{edition}-rN.json
├─ context/YYYY-MM-DD/{edition}-rN.json
├─ context/YYYY-MM-DD/{edition}-rN-authoring/
├─ content/{source_id}/{item_id}/...
├─ media/
│  ├─ images/
│  └─ image-cache.json
├─ reports/
│  ├─ index.html
│  └─ YYYY-MM-DD/{edition}-rN.{json,md,html,pdf}
├─ evaluations/YYYY-MM-DD/...
├─ state/
├─ publishing/
├─ challenges/
├─ retrospectives/
└─ locks/
```

所有 Run、Index、Context、正文、Report 和 Evaluation 路径都必须位于绑定的数据根。`runtime.py` 负责拒绝跨根 Artifact。

## 兼容结构

旧 source-index 可能同时或分别包含根级 `items` 与 `sources[].items`。读取逻辑兼容两层；正文更新后由 `synchronize_nested_items()` 同步。旧栏目别名由 `taxonomy.py` 集中映射，调用方不得自行维护另一份兼容表。
