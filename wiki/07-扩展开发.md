# 扩展开发

## 先选择扩展层

| 需求 | 修改位置 |
| --- | --- |
| 只进入零 Token 新闻流 | `configs/discovery-sources.yaml` |
| 进入正式日报覆盖 | `configs/sources.yaml` |
| 新 Feed/静态 HTML 协议 | `feeds.py` / `monitor.py` |
| 特殊来源结构或 API | `adapters.py` |
| 新正文规则 | `content.py` + 来源 selector |
| 新报告栏目/字段 | taxonomy、Schema、模板、编译、所有投影 |
| 新远程发布目标 | 独立 Publisher + Registry |

发现来源默认 `report_target: 0`、`report_max: 0`，不能仅因加入监控而扩大日报写作配额。

## 添加发现来源

在 `configs/discovery-sources.yaml` 添加最小 SourceConfig：

```yaml
- id: example_discovery
  name: Example Discovery
  url: https://news.example/
  bundle: discovery
  tier: 3
  role: discovery
  module: information
  category: international
  language: en
  region: global
  feed_urls:
    - https://news.example/feed.xml
  include_domains:
    - news.example
  article_patterns:
    - '^https://news\.example/articles/.+$'
```

这里的 `SourceConfig.language` 描述来源内容语言，不是报告输出语言。报告语言由 `output.language` 或 `run-edition --language` 选择；新增 Adapter 必须把来源语言保留在 item metadata，供译题字段和语言校验使用。

检查：

- ID 在核心与发现配置中全局唯一；
- Feed URL 和文章域名匹配；
- `bundle`、`tier`、`role` 反映来源用途；
- 发现来源不设置正数日报配额；
- Feed 返回空或失败时的状态可区分；
- 增加 Feed 解析、URL 过滤和 Monitor 状态测试。

## 添加核心来源

通用来源优先只改 `configs/sources.yaml`：

```yaml
- id: example_news
  name: Example News
  enabled: true
  mode: browser_index
  bundle: core
  tier: 2
  role: evidence
  url: https://news.example/
  feed_urls:
    - https://news.example/rss
  include_domains:
    - news.example
  article_patterns:
    - '^https://news\.example/articles/.+$'
  exclude_patterns:
    - '/authors/'
    - '/tags/'
    - '/search'
  exclude_title_patterns:
    - '^Sign in$'
  content_selectors:
    - article
    - main
  max_items: 60
  report_target: 10
  report_max: 15
  module: information
  category: international
  language: en
  region: global
```

至少测试：

- 一个合法文章 URL；
- 作者、标签、评论、登录或搜索噪音 URL；
- 中文/外文标题清洗；
- 发布时间解析；
- `report_target <= report_max <= budget.report_items_per_source`；
- 访问失败不会转成 `no_items`。

## Feed 与监控扩展

新增 Feed 行为时优先扩展 `feeds.py` 的通用解析：

- RSS 2.0、Atom 和常见命名空间；
- `link`、`guid`、`content`、`summary`、媒体图片；
- RFC/ISO 日期；
- Provider 元数据；
- 相对 URL；
- ETag、Last-Modified 和 `Retry-After`。

不得为单一站点在 Monitor 层复制一套网络客户端。来源特殊字段应通过小型、可测试的 Adapter 或配置消化。

修改聚类算法时必须测试：

- 相同规范 URL；
- 相似/不相似标题；
- 跨 96 小时时间边界；
- 不同 module 不合并；
- 稳定 `story_id`；
- `new/developing/confirmed/updated`；
- 代表条目与重要性稳定。

## 添加多栏目页

固定栏目放入 `explore_urls`。运行时发现的长期栏目使用：

```powershell
daily-intel source-page add `
  --source example_news `
  --url https://news.example/technology `
  --reason "新增技术栏目"
```

动态栏目保存在 `DATA_DIR/state/source-pages.json`：

- 只允许绝对 HTTP(S)；
- 主机属于入口域或 `include_domains`；
- 每来源最多五个；
- 必须是栏目/索引页，不能是文章、登录、搜索噪音或跨域页；
- 运行复盘不能自动写回仓库 YAML。

## 添加 Adapter

仅在通用 `browser_index`、Feed 或静态 HTML 无法稳定表达来源协议时新增 Adapter。

1. 在 `adapters.py` 实现返回 `ArticleItem` 的解析函数。
2. 使用公共 `_article()` 和 URL 规范化路径。
3. 注册到 Adapter Registry。
4. 在 SourceConfig 中设置 `adapter` 或 `mode`。
5. 覆盖成功、空结果、异常、日期、图片、去重和上限测试。

Adapter 不负责：

- 写 Index；
- 切换 Run 状态；
- 分配 Revision；
- 读取模型；
- 发布报告。

## 添加正文规则

优先在来源配置增加 `content_selectors`。只有跨来源通用行为才修改 `content.py`。

变更时测试：

- HTTP 提取成功；
- 已有正文复用；
- 脚本、样式、导航和页脚清理；
- JavaScript 空壳识别；
- HTTP 失败后的有条件浏览器回退；
- 同域串行/并发边界；
- `full_text/partial/metadata_only/failed` 映射；
- 根级与嵌套 Index 同步。

## 添加图片能力

不得绕过 `media.py` 直接下载。新图片来源或格式需要保持：

- 公共 HTTP(S) 与 DNS 检查；
- 响应大小、总预算、像素和 Raster 格式边界；
- 占位 URL、低信息 Raster 过滤和同新闻候选回退；
- 内容 Hash 存储；
- 成功/失败缓存；
- 全局与同域并发；
- 本地 HTML、桌面 HTML、PDF 和 Notion 投影一致。

图片失败不能改变 Brief 的事实内容或访问状态。

## 添加分类或分析域

修改顺序：

1. `taxonomy.py` 枚举、栏目 ID、顺序和标题；
2. `schemas/report.schema.json`；
3. `templates/report-contract.md`；
4. `context.py` / `authoring.py` Packet；
5. `reporting.py` 编译与校验；
6. Markdown、HTML、PDF 和 Notion；
7. 连续状态与 Evaluation；
8. 来源配置、测试、Wiki 和 Changelog。

固定栏目或分析域变化属于契约升级，必须说明旧报告如何读取、新 Context 如何阻止旧草稿绕过。

## 添加报告字段

先判断字段归属：

| 类型 | 位置 |
| --- | --- |
| 模型语义 | 写作模板/Packet，报告 Schema |
| 确定性身份 | `compile_report_data()` 注入 |
| 运行/指标 | Run 或 Authoring Session |
| 发布进度 | Tail / Registry |
| 展示专用 | HTML/PDF/Notion 投影，不进入事实源 |

报告字段通常需要同步 Schema、模板、装配、编译、校验、Markdown、HTML/PDF、Notion、Evaluation 和兼容读取。

## 添加本地输出

本地输出必须从已校验 Report 构建，并遵守：

- 文本转义和安全 URL；
- 原子写；
- 不修改 Report；
- 失败返回明确 warning；
- Evaluation 完成后可重建；
- 新格式不应自动成为远程发布。

桌面输出是 HTML 的第二个目标投影。修改 HTML 时同时测试归档相对链接与桌面绝对链接。

## 添加 Publisher

Publisher 只能接收已校验 Report：

- 目标 Schema 校验；
- 幂等键与本地 Registry；
- 中断续传；
- 显式重发；
- 独立错误状态；
- 不修改 Report 和 Hash；
- Fake Client 测试，不依赖真实凭证；
- Tail 中失败可重试，不影响本地完成状态。

## 变更检查

- [ ] 选对核心/发现来源层；
- [ ] 新输入按不可信数据处理；
- [ ] 状态没有退化为布尔值或空数组；
- [ ] 路径位于活动数据根；
- [ ] 不覆盖不可变 Artifact；
- [ ] 旧索引和旧报告仍可读取；
- [ ] Context/Packet 保持有界；
- [ ] 本地、桌面、PDF 和远程投影已同步；
- [ ] 新行为包含失败与重试测试；
- [ ] README、Wiki、references 和 Changelog 各归其位。
