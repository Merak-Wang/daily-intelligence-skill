# 可靠性与安全

## 故障分类

| 故障 | 状态或处理 |
| --- | --- |
| 页面成功但无合格链接 | `no_items` |
| 部分入口成功 | `partial` |
| 登录、401/403、挑战 | `verification_required` |
| HTTP 429 或明确临时限制 | `rate_limited`，停止本轮重试 |
| 网络、解析、服务端或配置错误 | `failed` |
| 当前 Monitor 协议不可用 | Monitor `unsupported`，不冒充正式 `no_items` |
| 正文不可访问 | 保留元数据与对应 `ContentStatus` |
| 桌面目录不可写 | `desktop_html_error` + warning |
| PDF、Notion 或评估失败 | Tail `partial`，本地报告保持完成 |

状态判断集中在 `access.py`、`feeds.py`、`monitor.py`、`prefetch.py`、`collector.py` 和 `content.py`。调用方不得自行把错误转换为成功或空结果。

## 分层降级

系统只允许显式、可审计的降级：

- Feed 失败可回退静态 HTML；
- 静态 HTML 无法提供公开内容时可记录待验证，不自动开 GUI；
- 正文 HTTP 失败且页面可能受益时才回退 Edge；
- PDF Edge 失败可回退 ReportLab；
- Brief 批次只有超过分析截止后才可 `--allow-degraded`；
- Notion 或 Evaluation 失败不撤回本地事实源。

降级不能提升证据等级、扩大访问权限或隐藏覆盖缺口。

## 写入与并发

- `write_json()`、`write_text_atomic()`、`write_bytes_atomic()` 使用临时文件替换。
- `write_immutable_json()` 拒绝覆盖已有 Artifact。
- `next_revision()` 只扫描目标类型的已有 Revision。
- `exclusive_lock()` 使用独占创建保护同一 edition。
- Feed、HTML、正文和图片都有全局/同域并发。
- Feed Cache、图片 Cache、Run 和发布登记必须在异常后仍可解析。

锁包含 PID、edition 和创建时间。遇到遗留锁时先确认进程与 Run，不直接删除整个 `locks/`。

## 唯一数据根

`runtime.py`：

- 绑定 Hermes 实例的唯一 `DATA_DIR`；
- 拒绝 CLI 与环境变量指向不同路径；
- 校验 Run、Index、Context、正文、Report 和 Evaluation 路径；
- 防止手动、计划任务和多个安装副本分裂历史。

查看与迁移：

```powershell
daily-intel data-root status
daily-intel --data-dir NEW_ROOT data-root adopt
```

迁移必须是显式操作；不能通过复制单个 Report 或修改 Run 路径伪造。

## 外部内容

Feed、HTML、API、正文、图片和模型草稿都是不可信输入：

- Feed 使用有界 XML 解析；
- 静态 HTML 使用 BeautifulSoup，不执行脚本；
- 浏览器只提取指定 DOM 数据，不执行页面文字指令；
- URL 经过协议、域名和正则过滤；
- HTML 投影转义文本，外链限制为安全协议；
- 模型 Packet 明确标注 `untrusted_data_notice`；
- Notion 块只从已校验 Report 构建。

动态栏目只能通过 `source-page add` 显式批准，并受同域与每来源五页限制。

## 图片安全

`media.py` 在下载前后执行：

- 只允许 HTTP(S)；
- 在采集和下载边界拒绝已知 placeholder/no-image URL；
- 拒绝本机、私网、链路本地、保留和不可路由地址；
- 代理 fake-IP 环境下进行独立公共 DNS 确认；
- 限制重定向次数、响应大小和总预算；
- 使用 Pillow 验证实际 Raster 格式、尺寸、像素数，并拒绝纯色或近纯色的低信息图片；
- 按内容 SHA-256 保存，不信任扩展名；
- 成功缓存与失败重试窗口分离；图片质量策略升级时提高缓存 Schema，旧成功项不会绕过新校验。

同一新闻保留有序图片候选，主候选失败后继续尝试后备候选；全部失败时不渲染图片区域。图片失败只影响配图，不改变新闻事实或阻断整个报告。

## 浏览器数据

浏览器 Profile 只用于合法登录和人工验证。以下内容不得提交、复制到 Skill 目录、示例或发布目标：

- Cookie、Storage State 和 HAR；
- 浏览器 Profile；
- 账户截图；
- 原始认证 HTML；
- 登录后 API 响应；
- 运行时 `data/`、正文缓存和验证页面。

PDF 的 Edge 渲染会阻止 HTTP(S) 网络请求，使用已经落盘的本地 HTML 与图片。

## 凭证

- Notion Token 只通过环境变量或外部密钥管理器。
- `.env`、`.env.*` 被忽略，`.env.example` 只保留空键名。
- 错误和指标不得输出 Token、Cookie、Authorization Header 或认证响应。
- 示例 HTML 必须扫描本机绝对路径和凭证模式。
- 泄漏后立即轮换，并检查 Git 历史和远程 Artifact。

## 前台交付可靠性

本地保存顺序：

1. 编译与预校验；
2. 图片绑定与最终校验；
3. 不可变 JSON/Markdown；
4. 本地 HTML；
5. 桌面 HTML；
6. 派生状态。

预校验同时检查 `language` 只能是 `zh-CN` 或 `en`，并要求标题、摘要、译题、研判及确定性栏目标签与之匹配。HTML 的 `lang`、Markdown、PDF 和 Notion 标签从已校验 Report 读取，不从当前机器配置重新猜测。

本地投影失败发生在事实源保存后，必须返回 warning 和恢复信息。桌面投影使用绝对本地链接，避免普通复制后图片失效。

## Tail 与远程发布

- Tail 只接受本地完成的 Run。
- PDF、Notion 和 Evaluation 分别记录状态与里程碑。
- Notion 使用本地 Registry 保存页面 ID 和追加进度。
- `--republish` 允许显式重发，但不绕过 Report 校验。
- Tail `partial` 可以重试；重复完成的步骤应跳过。
- Evaluation 调度最多三次；已有 completed Evaluation 时后续尝试直接退出。

HTML、桌面 HTML、PDF 和 Notion 都不能修改 Report Hash。

## 安全与隐私检查

发布前至少执行：

```powershell
git status --short
git diff --check
rg -n -i "token|secret|cookie|storage.state|authorization|BEGIN PRIVATE" .
rg -n -i "C:\\Users|/home/|AppData|file:///" examples
```

搜索结果需要人工区分变量名、公开新闻字符串、合成 Fixture 与真实敏感数据。

## 事故处理

| 事件 | 动作 |
| --- | --- |
| 数据根分裂 | 停止写入，比较 Registry 和 Run，再显式 adopt |
| 错误覆盖历史 | 保留现场，恢复上一 Revision，补防覆盖测试 |
| Token 泄漏 | 轮换、撤销授权、检查历史与远程发布 |
| 认证内容入库 | 从工作区与历史移除，重新审计忽略规则 |
| 状态误记为 `no_items` | 修正分类器，补访问失败回归测试 |
| 桌面/Notion 误发布 | 删除投影副本；本地事实源保持，修正目标配置 |
